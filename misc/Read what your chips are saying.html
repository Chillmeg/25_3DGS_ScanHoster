Scope vs analyzer

An oscilloscope shows the real voltage on one or two wires. A logic analyzer only cares whether each wire is HIGH or LOW, but it watches 8 wires at once, records for seconds instead of milliseconds, and can translate what it saw into bytes.

Oscilloscope

Answers "is the voltage right?" Shows curves, slow edges, noise.

Best for: power problems, analog signals, the shape of an edge.

Logic analyzer

Answers "is the data right?" Everything becomes a clean 1 or 0.

Best for: I2C, UART, SPI, timing between many pins.

The cheap 8-channel analyzers most labs have (a small box with a USB port and 10 wires) work fine for everything here.

Prep before the session

Most of what goes wrong with a logic analyzer happens before the first capture: drivers, wires, and not knowing which pin is which. Do these once on the lab laptop.

Software

  1. Install PulseView from sigrok.org. If your lab has a real Saleae, install Saleae's Logic 2 instead; the steps below map almost one to one.
  2. Open PulseView, choose Demo device from the device list, and press Run. Play with zooming and adding a decoder before any hardware is involved.
  3. Plug in the analyzer. It usually appears as "Saleae Logic" or under the driver fx2lafw.
  4. On a Windows laptop, Smart App Control blocks PulseView's installer. Skip the Windows version and follow On Windows: use WSL below instead.
  5. Have the Arduino IDE (or Thonny) ready with the four sketches below, and check one upload works. If it says "No drive to deploy", hold the XIAO's B button while plugging it in, then upload again.

Hardware

  1. A QPAD that works: the screen lights up with Quentin's example running.
  2. Female jumper wires or hook clips for the analyzer's leads. The OLED's four header pins on the back of the QPAD (GND, VCC, SCL, SDA) are the easiest place to attach.
  3. Confirm which XIAO pins the screen uses. The XIAO's default I2C pins are D4 (SDA) and D5 (SCL), and this guide assumes the QPAD uses those.
  4. Check that D6 isn't wired to anything on the QPAD, since experiment 2 sends text out of it.

Words you'll hear

The analyzer

Channel
One input wire on the analyzer. Labeled D0–D7 in PulseView, which is confusing because the XIAO also has pins called D0–D7. They are different things.In this guide, analyzer inputs are always called CH0, CH1, CH2.
Threshold
The voltage where the analyzer decides HIGH vs LOW, usually around 1.4 V. Anything above is a 1, anything below is a 0.
Sample rate
How many times per second the analyzer checks each wire. Use at least 4 to 10 times the speed of the signal, or short pulses get missed.
Samples
How many checks to record. Samples ÷ sample rate = capture length. 1 M samples at 1 MHz is one second.
Trigger
A condition that starts the recording, like "when CH1 goes low". Useful for catching one rare event.
Decoder
PulseView's translator. You tell it "these wires are I2C" and it writes the bytes above the waveform. The labels it writes are called annotations.

Numbers

Bit, byte
A bit is one 0 or 1. A byte is 8 bits, a number from 0 to 255.
Hex, 0x
A short way to write bytes. 0x3C means 60. Every byte is two hex digits, 00 to FF.
ASCII
The table that turns bytes into letters: 0x48 is "H", 0x69 is "i".
MSB, LSB
Most and least significant bit: the "big" and "small" end of a byte. I2C sends the MSB first; UART sends the LSB first.

UART

TX, RX
Transmit and receive. One wire per direction, no clock. On the XIAO, TX is D6.
Baud rate
Bits per second. Both sides must agree on it in advance: 9600 means each bit lasts about 104 µs.
Frame
One character on the wire: a start bit (LOW), 8 data bits, a stop bit (HIGH). The line rests HIGH when idle. Called 8N1.

I2C

SCL, SDA
Clock and data. The XIAO ticks the clock; on each tick the data wire is read as one bit.
Start, stop
Every message begins with SDA falling while SCL is high (start) and ends with SDA rising while SCL is high (stop).
Address
Each chip on the wires has a number. The QPAD's screen is usually 0x3C. The first byte of every message is the address plus one bit saying write (0) or read (1).
ACK, NACK
After every byte, the receiver pulls SDA low to say "got it" (ACK). If nobody pulls it low, that's a NACK: nobody is listening at that address.

On Windows: use WSL

If you have a Windows laptop, we're going to use WSL to run PulseView. The following is how you do it.

Windows Smart App Control blocks PulseView's Windows installer because it isn't digitally signed (it's a volunteer open-source project, not malware). Instead of turning off a security feature, we run the Linux version of PulseView inside WSL, the Windows Subsystem for Linux, and pass the analyzer's USB connection into it with a small Microsoft-supported tool called usbipd-win.

This is for the HiLetgo analyzer. The Kingst uses KingstVIS directly in Windows. On a Mac or Linux laptop, install PulseView normally and skip this section.

Before you start

You need Windows 11 with WSL2 and Ubuntu. To check, open PowerShell and run wsl -l -v: Ubuntu should be listed with VERSION 2. If WSL isn't installed, run wsl --install in an administrator PowerShell and restart.

You'll type commands in two different places, and mixing them up is the most common mistake:

  • PowerShell is Windows. Open it from the Start menu. Some steps need Run as administrator (right-click PowerShell, choose Run as administrator); the prompt then reads C:\windows\system32>.
  • Ubuntu is Linux inside WSL. Open the Ubuntu app; the prompt looks like yourname@yourpc:~$.

One-time setup

1. Install usbipd-win.

PowerShell 
winget install usbipd

If it says "winget not found", you're probably in the Ubuntu terminal by mistake. If you're in PowerShell, install App Installer from the Microsoft Store (it includes winget), or download the .msi from the usbipd-win releases page on GitHub (github.com/dorssel/usbipd-win/releases) and double-click it. Close and reopen PowerShell afterwards.

2. Find the analyzer. Plug it in, then:

PowerShell 
usbipd list

Find the row with VID:PID 0925:3881. It's listed as "Unknown device". Write down its BUSID; it depends on the USB port, so yours may differ from this example:

BUSID  VID:PID    DEVICE                        STATE
2-2    187c:0551  USB Input Device              Not shared
2-5    0925:3881  Unknown device                Not shared   <- the analyzer
2-6    0bda:558b  Integrated Webcam ...         Not shared

Replace 2-5 in every command below with your own BUSID.

3. Share it with WSL. This needs administrator rights, and you only do it once.

PowerShell (administrator) 
usbipd bind --busid 2-5

"Access denied" means the PowerShell window isn't running as administrator.

4. Install PulseView in Ubuntu.

Ubuntu 
sudo apt update
sudo apt install pulseview sigrok-firmware-fx2lafw usbutils x11-apps

That's PulseView, the analyzer's firmware, lsusb for checking USB, and xeyes for testing that Linux windows show up. sudo asks for your Ubuntu password; nothing appears as you type it.

Every time you use the analyzer

1. Plug in the analyzer.

2. Attach it to WSL (no administrator needed):

PowerShell 
usbipd attach --wsl --busid 2-5 --auto-attach

Wait for Device 2-5 is now attached, then leave this window open. Don't press Ctrl+C. When PulseView first connects, it loads firmware onto the analyzer, which makes it disconnect and reconnect; --auto-attach reattaches it automatically, so you'll see a few more detach and attach lines. That's normal.

3. Check WSL can see it.

Ubuntu 
lsusb

You should see a line with 0925:3881, or 1d50:608c if PulseView already loaded its firmware.

4. Start PulseView.

Ubuntu 
sudo pulseview

A PulseView window opens like a normal Windows app. You can ignore messages like XDG_RUNTIME_DIR not set and bt-bluez: devid failed; they're harmless.

5. Pick the analyzer. If the device dropdown in the toolbar already says Saleae Logic with channels D0 to D7, you're done. If it says Demo device: open the dropdown, choose Connect to Device, pick the driver fx2lafw, leave USB selected, click Scan for devices using driver above, select Saleae Logic, and click OK.

6. Test. Set 1 MHz and 1 M samples, click Run. With nothing connected you get flat lines on all eight channels. Everything works; go to experiment 1.

PulseView basics

Every experiment uses the same five moves. Learn them once with the Demo device.

  1. Pick the device from the dropdown at the top left. Click the channel names to hide the ones you aren't using.
  2. Set sample rate and samples in the two boxes next to it. Each experiment below gives values.
  3. Press Run. The capture fills in after the set time.
  4. Zoom and measure. Scroll to zoom, drag to pan. Click the cursor button to drop two markers; the time between them shows at the top.
  5. Add a decoder. Click the yellow-and-green decoder icon, type the protocol name (UART, I2C), then click the new row's label to assign channels and settings.

Always connect the analyzer's GND lead to the QPAD's GND before anything else. Without a shared ground the analyzer sees garbage.
