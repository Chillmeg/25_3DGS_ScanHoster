Logic analyzer on Windows: quick start

The commands to run every time you restart, and what to do when the analyzer won't attach. For the HiLetgo analyzer, running PulseView inside WSL.

Every time you restart

Setup is remembered, so after a restart you only need two commands.

1. Plug in the analyzer, then attach it to WSL. Normal PowerShell, no administrator needed:

PowerShell 
usbipd attach --wsl --busid 2-5 --auto-attach

Wait for Device 2-5 is now attached. Leave this window open.

2. Start PulseView:

Ubuntu 
sudo pulseview

The toolbar should say Saleae Logic. If it says Demo device: open the dropdown, Connect to Device, driver fx2lafw, Scan, select Saleae Logic, OK.

Ignore XDG_RUNTIME_DIR not set and bt-bluez: devid failed. They're harmless.

"Failed to attach device"

The loop sees the analyzer on the Windows side, but WSL can't connect to it. Press Ctrl+C to stop the loop, then work through these in order.

1. Load WSL's USB support. After a restart it sometimes isn't loaded yet. Make sure Ubuntu is open, then:

Ubuntu 
sudo modprobe vhci_hcd

2. Clear any leftover state and check the analyzer is shared:

PowerShell 
usbipd detach --busid 2-5
usbipd list

The 2-5 row should say Shared. If it says Not shared, share it again from an administrator PowerShell (right-click PowerShell, Run as administrator):

PowerShell (administrator) 
usbipd bind --busid 2-5

3. Attach once without the loop, so it prints the real error instead of retrying:

PowerShell 
usbipd attach --wsl --busid 2-5

If that works, go back to the normal --auto-attach command above.

4. Still failing? Check your network. A VPN (like MIT's Cisco VPN) or a firewall change can block WSL from reaching Windows. Disconnect the VPN and try step 3 again.

5. Last resort: restart WSL.

PowerShell 
wsl --shutdown

Reopen Ubuntu, run step 1 again, then attach.

Other problems

What you seeFix
There is no device with busidThe analyzer is in a different USB port. Run usbipd list, find the 0925:3881 row, and use its BUSID. The first time on a new port, bind it as administrator.
Access deniedThat command needs an administrator PowerShell.
lsusb in Ubuntu prints nothingNot attached. Go through "Failed to attach device" above.
PulseView scan finds nothingCheck lsusb shows 0925:3881 or 1d50:608c. Make sure you started PulseView with sudo.
PulseView icon on the taskbar, no windowClick the icon, press Alt+Space, then M, tap an arrow key and move the mouse. Or start it with sudo QT_QPA_PLATFORM=xcb pulseview.
Overflow errors when capturingLower the sample rate. 4 MHz is enough for the QPAD's I2C.

When you're done

  1. Re-upload the QPAD example so the board is back to normal.
  2. Close PulseView.
  3. Press Ctrl+C in the PowerShell window to stop the attach loop.

BUSID 2-5 is this laptop's port; yours may differ. Full setup, experiments and explanations: the "Read what your chips are saying" logic analyzer guide.
